# 私の要求

## 背景

`output_data` フォルダに、2,500冊超の書籍のAI要約データ（Markdown形式）がある。これをデータベース化し、AI・プログラムの両方から読み取りやすい形にしたい。

## やりたいこと

1. Claude Code / Antigravity CLI などのAIに「司書」として質問を投げられるようにしたい。例:
   - 「会計について勉強したいので、勉強するために最適な本を蔵書からすべて挙げ、NotebookLMのソースとして登録してください」（NotebookLM登録部分は別プログラムで実装予定）
   - 「英語初心者の私が、まずは英語をしゃべるために役立つ本を3冊紹介してください」
   - 「ルネサンスの食文化について調べたいので、それに言及している本を紹介してください」
2. 上記を実現するためにデータが不足している場合は、現状データを基に外部APIなどで補足することも検討する。
3. 上記以外にもできそうなことがあればアドバイスしてほしい。単に本を紹介されて読むだけでなく、NotebookLMなどを使ってその内容を加工し、自分のアウトプットに役立てたい。
4. AIが利用しやすいデータ形式を検討する（MCPなども視野に入れつつ）。現状データを最大限活用し、将来的な拡張（他用途への応用）が可能なプラットフォームにしたい。プログラムで読み出せるということは、将来それを使って拡張（他への応用）ができるということでもある。

## 検討を重ねて明確になった要求（追加ヒアリングで確定した内容）

- 新規実装は元プロジェクト（`20260702_summarize_book_with_gemini`）とは別の新規フォルダに一から作る。元プロジェクトのコード（index.js/lib/gui等）は再利用しない。参照するのは `output_data` フォルダのデータのみ。
- `output_data` は今後も本が追加されて増え続けるため、データベースは差分更新（新規・更新・削除ファイルの検知）に対応する必要がある。
- `蔵書リスト.csv` も `output_data` と同様に随時更新される（本の追加・情報更新）。そのためDB更新処理は `output_data` の差分検知だけでなく、`蔵書リスト.csv` の再取り込みにも対応する必要がある。
- 最も重要な要件は単なる「検索ツール」ではなく、**司書／書籍に精通したメンターとしてユーザーに実践させるAI**であること。
- 応答は2段階とする: まず現状データ（output_data由来のローカルDB）で回答する。それだけでは不十分と判断した場合、ユーザーに確認した上でNotebookLM等の外部ツールに橋渡しして深掘りを実行する。
- NotebookLM以外の学習支援ツール（Obsidian、Anki等）も将来つなげられるよう、橋渡し部分は拡張可能な構造にする。
- ISBN・NDC分類などの外部API補完は今回のフェーズには含めないが、後から実装できるようスキーマ上の余地を残し、開発項目として記録しておく。
- 実装言語はNode.js。
- 新規プロジェクトの配置場所は `C:\Users\okada\src\20260725_book_librarian`。`output_data` はジャンクションでリンクし、他に有用なデータ（`蔵書リスト.csv`）もリンクする。
