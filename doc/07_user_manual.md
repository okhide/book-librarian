# ユーザーマニュアル（PC初心者向け）

このマニュアルは、パソコンは使うけれど「しくみ」には詳しくない、という方向けに書いています。コマンド（キーボードで文字を打って実行する操作）が初めての方でも、順番に進めれば使えるように説明します。

## 1. このプログラムは何をするもの？

あなたの蔵書（本の要約データ）を検索できるデータベースにし、AI（Claude）が「司書さん」として、本の検索・おすすめ・読書の進捗管理を手伝ってくれるようにするプログラムです。

- 「〇〇について勉強したい」と言うと、関連する本を探して提案してくれる
- キーワードが一致しなくても、意味的に近い本を見つけてくれる（例:「ルネサンス期の食文化」で検索すると、直接その言葉が無くてもルネサンス史の本などを教えてくれる）
- 読んだ本・読みたい本を記録して、次に読むべき本を一緒に考えてくれる
- 蔵書の中に似たような本（買った本人も忘れていた重複）がないか調べられる

## 2. 必要なものリスト

| 項目                                        | 必須/任意                              | 何のために使うか                                     |
| ------------------------------------------- | -------------------------------------- | ---------------------------------------------------- |
| Windows/Mac/LinuxのPC                       | 必須                                   | このプログラムを動かす場所                           |
| Node.js（バージョン20以上）                 | 必須                                   | このプログラムを実行するための基盤ソフト             |
| Claude Code                                 | 必須                                   | AI司書と会話するためのツール                         |
| Anthropicのアカウント（Claude Code用）      | 必須                                   | Claude Codeを使うために必要                          |
| Gemini APIキー                              | 蔵書データベースを最初に作る時だけ必須 | 本のジャンル分類などをAIに手伝わせるため             |
| notebooklm CLI（notebooklm-py）             | 任意                                   | 「NotebookLMに登録して深く調べる」機能を使う場合のみ |
| 蔵書の要約データ（`data/output_data/`など） | 必須                                   | 検索対象となる本のデータそのもの                     |

「蔵書の要約データ」は、このプログラム単体では作れません。本のPDF等から要約を作る別プロジェクトの出力を読み込む前提で作られています（詳細は`03_specification.md`の「データソース」参照）。すでに用意されている場合はそのまま次に進んでください。

## 3. セットアップ手順

### 3.1 Node.jsのインストール

1. [https://nodejs.org/](https://nodejs.org/) を開く（**入力の必要はありません。あなた自身でこのURLをブラウザに入力してアクセスしてください**）。
2. 「LTS」と書かれている方のバージョン（安定版）をダウンロードしてインストールする。インストーラの指示に従って「次へ」を押していけば完了します。
3. インストールできたか確認する。ターミナル（Windowsなら「PowerShell」、Macなら「ターミナル」）を開き、次を入力してEnter:
   ```
   node --version
   ```
   `v20.0.0` のように数字が表示されればOKです。

### 3.2 Claude Codeのインストールとログイン

Claude Codeは、AI（Claude）にパソコン上の作業を手伝わせるためのアプリです。このプロジェクトの「AI司書」機能は、Claude Code上で動く前提で作られています。

1. ターミナルで次を実行してインストールする:
   ```
   npm install -g @anthropic-ai/claude-code
   ```
2. インストールできたら、プロジェクトのフォルダ（このマニュアルがある場所）に移動し、`claude` と入力してEnterで起動する。
3. 初回はブラウザでのログインを求められます。画面の指示に従ってAnthropicのアカウントでログインしてください。

> 📌 **Claude Desktop appとの違い**: 「Claude」という名前のスマホ/PCアプリ（Claude Desktop app）もありますが、これは一般的な会話用のアプリで、このプロジェクトのファイルを直接操作したり、後述の「司書スキル」を使ったりすることはできません。**この蔵書プログラムを使うには、Claude Codeが必要です。** GeminiのアプリやWeb版も同様に、この蔵書プログラムの検索・司書機能そのものには使いません（Geminiは後述のとおり、データベースを最初に作る作業でのみ使います）。

### 3.3 プロジェクトの取得と依存パッケージのインストール

1. プロジェクトのフォルダをパソコンに用意する（GitHubからの取得方法は`README.md`を参照）。
2. ターミナルでそのフォルダに移動し、次を実行する:
   ```
   npm install
   ```
   これでこのプログラムが必要とする部品（ライブラリ）が自動的にダウンロードされます。数分かかることがあります。

### 3.4 Gemini APIキーの取得と設定（データベースを最初に作る時だけ）

蔵書データベースを最初に作るとき、本のジャンルを自動分類する処理でGoogleのGemini AIを使います（無料利用枠の範囲内で足ります）。**この設定は最初の1回だけで、普段の検索・司書機能では使いません。**

1. [https://aistudio.google.com/apikey](https://aistudio.google.com/apikey) を開き、GoogleアカウントでログインしてAPIキーを発行する。
2. プロジェクトのフォルダにある `.env.example` というファイルを `.env` という名前でコピーする。
3. `.env` ファイルを開き、`GEMINI_API_KEY=` の後ろに発行されたキーを貼り付けて保存する。
   ```
   GEMINI_API_KEY=ここに発行されたキーを貼り付け
   ```
   ※ `.env` ファイルはGitHubには公開されません（`.gitignore`で除外設定済み）。他人に見せたり共有したりしないでください。

### 3.5 （任意）NotebookLM連携を使う場合の準備

蔵書の中の本をGoogle NotebookLMに登録して、AIとチャットで深掘りしたりクイズを作ったりする機能を使いたい場合のみ必要です。使わないなら読み飛ばしてかまいません。

1. Pythonがインストールされていることを確認する（`python --version`）。
2. `pip install notebooklm-py`（または`pipx install notebooklm-py`）を実行してインストールする。
3. ターミナルで `notebooklm login` を実行し、ブラウザでGoogleアカウントにログインする（この操作は必ず自分の手でターミナルから行ってください。AIに代行させることはできません）。

### 3.6 蔵書データベースの構築（初回ビルド）

蔵書の要約データ（`data/output_data/`）が準備できていれば、次を実行してデータベースを作ります:

```
node src/build/build.js
```

数分かかります（本の件数と埋め込みモデルの読み込みに依存）。完了すると `data/db/library.db` というファイルができ、これがあなたの蔵書データベースです。

すでにこのデータベースが用意されている（誰かが構築済みの状態を受け取った）場合は、この手順は不要です。

### 3.7 （Windows）デスクトップに一発起動用のショートカットを作る

毎回ターミナルを開いてフォルダに移動し`claude`と入力するのが面倒な場合、デスクトップのアイコンをダブルクリックするだけで起動できるようにできます。

1. ターミナルでプロジェクトのフォルダに移動し、次を実行する:
   ```
   powershell -ExecutionPolicy Bypass -File scripts\create-desktop-shortcut.ps1
   ```
2. デスクトップに「蔵書AI司書」というショートカットが作成されます。以後はこれをダブルクリックするだけで、このプロジェクトのフォルダでClaude Codeが起動します。
3. **起動した瞬間に、司書AIが自動的に「何ができるか」のメニュー（蔵書規模・トピック例・聞き方の例）を提示します。** これは`start-librarian.bat`が`claude`起動時に`/book-librarian`（司書スキルを明示的に呼び出すコマンド）をあらかじめ渡しているためです（`4.2`のヘルプ導線がそのまま起動時に発動する仕組み）。そのまま気になるテーマを続けて話しかけてください。
4. **このフォルダで初めてClaude Codeを使う場合、最初の1回だけ「このワークスペースを信頼しますか」という確認が表示されます。** これはClaude Codeの標準的なセキュリティ確認で、このプロジェクトに限った話ではありません。内容を確認して承認してください。2回目以降は表示されません。

> 📌 Windowsのスタートメニューにある「Claude」というアプリ（一般的な会話用のClaude Desktop app）からも、フォルダを指定して同じように使えるかは確認できていません。**確実に動作するのは上記のショートカット（Claude Code CLIをこのフォルダで起動する方法）です。**

### 3.8 （Windows）手動でコマンドを打つためのターミナルショートカット

`notebooklm login`（ログインは必ず自分の手で行う必要がある）や`node src/build/build.js`（データベースの更新）を、AIに頼らず自分で直接実行したい場合のためのショートカットです。Claude Codeを起動しているウィンドウとは別に、もう1つ開いて併用できます。

```
powershell -ExecutionPolicy Bypass -File scripts\create-terminal-shortcut.ps1
```

デスクトップに「蔵書ターミナル」というショートカットが作成されます。ダブルクリックすると、このプロジェクトのフォルダを開いた状態のPowerShellが起動し、`npm run viewer`・`notebooklm login`・`node src/build/build.js`など、よく使う手動コマンドの一覧（バナー、`scripts\terminal-banner.ps1`）が表示されます。表示されたコマンドをそのままコピー＆ペーストして実行できます。

## 4. 基本的な使い方

### 4.1 AI司書との会話を始める

プロジェクトのフォルダでターミナルから `claude` と入力してClaude Codeを起動し、書きたいことをそのまま日本語で話しかけてください。例:

```
会計について勉強したいです
```

Claude Codeが自動的に「司書スキル」を使って蔵書を検索し、結果を教えてくれます。

### 4.2 何を聞けばいいか分からないとき

そのまま「何かおすすめある？」「何ができるの？」と聞いてください。司書AIが蔵書の規模や実際のジャンル一覧を示しながら、聞き方の例を提案してくれます。

### 4.3 よくある聞き方の例（ユースケース）

| やりたいこと                 | 聞き方の例                                                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| テーマで本を探す             | 「投資について勉強したい」                                                                                         |
| レベルを指定して探す         | 「統計学の初心者向けに3冊教えて」                                                                                  |
| 似た本を探す                 | 「〇〇（本のタイトル）に似た本はある？」                                                                           |
| 蔵書の傾向を知る             | 「うちの本棚にはどんなジャンルが多い？」「足りないジャンルは？」                                                   |
| 複数の本の意見をまとめて聞く | 「投資について、蔵書は総じて何を言っている？」                                                                     |
| 読んだ本を記録する           | 「〇〇を読み終わった、評価は5点」                                                                                  |
| 積んでいる本を掘り起こす     | 「読んでいない本の中で長く放置されているものは？」                                                                 |
| 学習の進捗を相談する         | 「会計の勉強、どこまで進んだ？次は何を読むべき？」                                                                 |
| 重複した本がないか調べる     | 「同じような本を何冊も買ってない？」                                                                               |
| 蔵書全体を俯瞰する           | 「私の蔵書って、そもそもどういう構成なの？」                                                                       |
| ニッチな話題を深掘りする     | 「〇〇についてもっと詳しく知りたい（蔵書の要約だけでは足りない場合）」→ 承認するとNotebookLMへの登録を提案されます |

司書AIは、勝手に少数の本だけを決め打ちで薦めることはせず、まずヒット件数を正直に伝え、対話しながら絞り込んでいきます。また、読んだ本・読書中の本を新しい提案として出さないよう既読状態を確認してから答えます。

### 4.4 ブラウザで検索・閲覧・読書状態の編集をする

AIと会話する代わりに、ブラウザから直接、蔵書を検索したり読書状態（未読/読書中/読了/中断・評価・メモ）を記録したりできる画面（ビューア）もあります。「〇〇を読み終わった」とAIに話しかける代わりに、この画面から記録することもできます。

1. ターミナルでプロジェクトのフォルダに移動し、次を実行する（Claude Codeとは別のターミナルウィンドウで実行してください。3.8のショートカットが使えます）:
   ```
   npm run viewer
   ```
2. 「蔵書ビューア: http://127.0.0.1:3000 を開いてください」と表示されたら、そのURLをブラウザ（Chrome等）に入力して開く。
3. 検索語を入力すると、入力するそばから結果が絞り込まれます。カテゴリ・トピック・出版年・読者レベル・未読のみ、での絞り込みも可能です。
4. 本のタイトルをクリックすると詳細画面が開きます。既定は**閲覧モード**で、その本のほぼ全てのデータ（書誌情報・要約・キーワード・トピック・ISBN/NDC補完結果・システム情報まで）を確認できます。「蔵書本体を開く（Google Drive）」のリンクがある本は、クリックすると新しいタブでその本の実体（Google Drive上のファイル）が開きます。
5. 詳細画面の下部で読書状態（未読/読書中/読了/中断）・評価（1〜5）・メモを入力し「保存」を押すと記録されます。

#### 詳細画面の編集モード

詳細画面右上の「✎ 編集モードに切り替え」を押すと、書誌情報・要約・読者レベルを直接書き換えられる**編集モード**になります。

- **編集できる項目**: タイトル・著者・出版社・シリーズ・版・ISBN・出版日・出版年・カテゴリ（元データ）・信頼度スコア・蔵書本体リンク・短い要約・長い要約・読者レベル
- **編集できない項目**（表示のみ）: キーワード・トピック（自動生成、変えたい場合は`data/topic_overrides.json`または5.4節の手順で）、ISBN/NDC自動補完の結果（`node src/cli/enrich.js`で扱う）、id・ファイルパス・状態(status)・各種ハッシュ・蔵書リスト連携情報などの内部管理用データ（変更すると差分更新やデータ突き合わせが壊れるため）
- 保存すると、変更内容に応じて検索用データが自動的に再合成されます。ISBNまたはタイトルを変更した場合は、その本のISBN/NDC補完結果が無効化され、次回の`node src/build/build.js`実行時に再補完の対象に戻ります。
- 「閲覧モードに戻る」を押すと、通常の（編集できない）表示に戻ります。

止めたいときは、実行しているターミナルで`Ctrl+C`を押してください。この画面はパソコン内だけで動くもので、インターネット上に公開されるものではありません。

## 5. メンテナンス

### 5.1 蔵書データの更新（新しい本が増えたとき）

元の要約データ（`data/output_data/`や`蔵書リスト.csv`）が更新されたら、次を実行するだけで、**変更があった本だけ**を検出して反映します（あなたが記録した読書状態は消えません）:

```
node src/build/build.js
```

このコマンド1回で、新しい本の追加・更新にまつわる一連の作業が自動的に行われます。

0. **蔵書リスト.csvの最新化**: 元プロジェクト側の最新のCSVを`data/蔵書リスト.csv`へ自動的にコピーします（元プロジェクトはこのファイルを都度作り直すため、毎回コピーし直すことで常に最新のGoogle Driveリンク等を参照できるようにしています）。元CSVが見つからない場合は警告を表示し、既存の内容のまま処理を続けます
1. **本の追加・更新の検出**: 新しいMarkdownファイルを取り込み、内容が変わったファイルは再解析します
2. **ジャンル分類の適用**: 既存の分類辞書（`data/topic_taxonomy.json`等）を使って、追加・変更された本にジャンルを割り当てます
3. **読者レベル判定**: タイトルの特徴（「入門」「詳解」等）から初心者/上級者向けを自動判定します
4. **検索用の埋め込み生成**: 意味検索・類似本検索のためのベクトルを生成します
5. **ISBN・NDC分類の外部API補完**: 国立国会図書館サーチ（NDL）等に問い合わせ、ISBN・日本十進分類法（NDC）を自動的に埋めます（後述）

実行結果には、各段階の件数（新規〇件、ジャンル分類の再適用〇件、等）が表示されます。

#### 一括更新の一連の流れ（本の追加・更新をまとめて反映する手順）

本を大量に追加したときや、しばらくぶりに更新するときは、次の順番で実行すると、ジャンル分類・読者レベル・ISBN/NDCが漏れなく揃った状態にできます。

1. `node src/build/build.js` を実行する
2. 実行結果に「⚠ reader_level未判定の本がN件あります」と出た場合、`node src/build/runReaderLevelLlm.js` を実行する（ルールで判定できなかった本だけをGemini APIで補完。件数が少なければ無料利用枠の範囲で収まります）
3. 実行結果に「対応表に無いキーワード」といった警告が出た場合、`node src/build/runTopicMapping.js` を実行する（新しいキーワードだけをGemini APIで分類し`data/topic_mapping.json`に追記）
4. 手順3を実行した場合は、その内容を本に反映するため、もう一度 `node src/build/build.js` を実行する
5. `data/output_data/`が随時増える環境（他プロジェクトと連携している等）では、1回の実行中にも新しい本がさらに見つかることがあります。「新規=0」になるまで1〜4を繰り返すと完全に反映できますが、必須ではありません（次回実行時に自動的に続きから処理されるため、待たずに切り上げても問題ありません）
6. 最後に `node src/cli/enrich.js review` で、ISBN・NDCがレビュー待ちになっている本が無いか確認する（後述）

途中で中断しても、次に実行したときに未処理分だけが自動的に処理されるので、やり直しの心配はありません。

#### ISBN・NDC分類の外部API補完について

新しく追加された本は、国立国会図書館サーチ（無料・登録不要）に自動的に問い合わせ、ISBN・NDC分類（日本十進分類法）を埋めます。加えて、Google Books API（`.env`に`GOOGLE_BOOKS_API_KEY`を設定した場合のみ・既定で有効）で、国立国会図書館に無い本のISBN確認を補助的に試みます。

自費出版のKindle本や雑誌の個別号など、そもそも外部のデータベースに存在しない本は「見つからない」扱いのままになります。また、タイトルが似た本が複数ヒットして自動的には決められない場合もあります。これらは自動判断せず、レビュー待ちとして溜まります。以下のコマンドでまとめて確認できます:

```
node src/cli/enrich.js review
```

内容を見て、手元の本の奥付等からISBNが分かる場合は次で手動確定できます:

```
node src/cli/enrich.js resolve --id <表示されたID> --isbn <ISBN>
```

レビュー不要と判断した場合は次で対象外にできます（一覧から消えます）:

```
node src/cli/enrich.js skip --id <表示されたID>
```

Google Books補完を使いたくない場合は、`.env`に`ENRICHMENT_GOOGLE_BOOKS_ENABLED=false`を追記してください。

### 5.2 フルリビルド（ジャンル分類のルールを変えたときなど）

通常は不要ですが、トピック分類の辞書やスキーマを大きく変えた場合は、次で全件を作り直せます（読書状態は保護されます）:

```
node src/build/build.js --full
```

### 5.3 感度調整（検索・重複検知・クラスタリングの微調整）

これらは「絶対の正解」がない設定値です。使ってみて多い/少ないと感じたら調整してください。

| 何を調整するか                 | コマンド例                                               | 既定値          | 増やすと                     | 減らすと                                     |
| ------------------------------ | -------------------------------------------------------- | --------------- | ---------------------------- | -------------------------------------------- |
| 意味検索だけでの「ヒット」判定 | `node src/cli/search.js "検索語" --vector-threshold 0.8` | 1.0（実質無効） | ヒット件数に厳しくなる       | 意味的に近いだけの本も件数に含まれやすくなる |
| 重複本の検出の厳しさ           | `node src/cli/duplicates.js --threshold 0.9`             | 0.95            | 検出件数が減り、精度は上がる | 検出件数が増え、別の本の誤検出も増える       |
| 蔵書俯瞰のクラスタ数           | `node src/cli/stats.js --clusters --k 15`                | 20              | より細かい塊に分かれる       | より大きな塊にまとまる                       |

これらのコマンドは司書AIとの会話中に自動的に使われますが、「もっと厳しく（緩く）調べて」と頼めば、AIが引数を調整して実行してくれます。

### 5.4 ジャンル分類の手直し

本のジャンル分類がおかしいと感じたら、`data/topic_overrides.json` を編集してください（キーワード→正しいジャンル名の対応を書く）。編集後に`node src/build/build.js`を実行すると反映されます。

ジャンルの一覧そのもの（2026-07-27時点で40種類）を見直したい場合は`data/topic_taxonomy.json`を編集してください。今の正確な件数と内訳は`node src/cli/topics.js`（蔵書ビューアの絞り込みメニューでも可）でいつでも確認できます。蔵書が増えると、既存のジャンルでは括りきれない本が増えてくることがあります。その場合は次の手順で、蔵書全体を見渡した上でジャンル一覧そのものを作り直せます（Gemini APIを使います）:

```
node src/build/runTaxonomyDraft.js
```

`data/topic_taxonomy.draft.json`という草案ファイルが生成されるので、内容を確認し、問題なければ`data/topic_taxonomy.json`として上書き保存してください（このコマンドは草案を作るだけで、既存のジャンル一覧を自動的には書き換えません）。採用したら、次の2つを順に実行して全冊に反映します:

```
node src/build/runTopicMapping.js --full
node src/build/build.js
```

1つ目（`--full`オプション）で全キーワードを新しいジャンル一覧に基づいて分類し直し、2つ目で全冊のジャンルを更新します（`--full`を付けないと、ジャンル一覧を変えた後も古い対応表がそのまま使われてしまうので注意してください）。

### 5.5 バックアップについて

`data/db/library.db`の中の`reading_status`という部分に、あなたが記録した読書状態（読んだ/評価/メモ）が入っています。**これは元データを再ビルドしても消えない設計になっていますが、このファイル自体を誤って削除・上書きすると失われます。** 定期的に`data/db/library.db`をコピーして別の場所に保存しておくことをおすすめします。

## 6. よくあるトラブル

| 症状                                           | 考えられる原因と対処                                                             |
| ---------------------------------------------- | -------------------------------------------------------------------------------- |
| `node`コマンドが見つからないと言われる         | Node.jsが正しくインストールされていません。3.1を再確認してください               |
| データベース構築時にGemini関連のエラーが出る   | `.env`のAPIキーが正しく設定されていないか、無料利用枠を超えています              |
| NotebookLM関連のコマンドで「認証エラー」と出る | ターミナルで`notebooklm login`を実行し直してください（AIには代行できません）     |
| 検索結果が0件ばかりになる                      | 蔵書データベースが未構築、または古い可能性があります。3.6・5.1を確認してください |
| 読書記録が消えたように見える                   | `data/db/library.db`を誤って削除・上書きしていないか確認してください（5.5参照）  |

## 7. 用語集

| 用語                        | 説明                                                                                               |
| --------------------------- | -------------------------------------------------------------------------------------------------- |
| CLI（コマンドラインツール） | ターミナルに文字を打って実行するタイプのプログラム                                                 |
| データベース                | 検索しやすいように整理して保存されたデータの集まり（このプログラムでは`library.db`というファイル） |
| 埋め込み（embedding）       | 文章の「意味」を数値の並びに変換したもの。意味的に近い文章ほど近い数値になる                       |
| ハイブリッド検索            | キーワードでの検索と、意味（埋め込み）での検索を組み合わせた検索方式                               |
| Skill（スキル）             | Claude Codeに特定の役割（このプロジェクトでは「司書」）を持たせる仕組み                            |
| トピック                    | あらかじめ決めたジャンル分類（2026-07-27時点で40種類。本の増加に応じて随時見直すため件数は変動する。5.4参照） |
| クラスタリング              | あらかじめ決めた分類ではなく、AIがデータ自体の似ている塊を見つけて自動的に分ける手法               |
